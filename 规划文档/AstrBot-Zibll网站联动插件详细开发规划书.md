## 3. 架构选择与范围

### 3.1 最小可行结构

```text
允许的群聊
    |
AstrBot：识别指令、提取真实发送者身份、调用接口、发送图片和文本
    |
HTTPS + 专用集成凭证 + 请求签名
    |
WordPress 伴随桥接插件：认证、绑定、权限、业务编排
    |
WordPress / Zibll 已有函数与数据
```

浏览器绑定流程单独走网站现有登录态和 CSRF 校验，不把网站 Cookie、密码或机器人密钥交给另一端。

| 部件 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| AstrBot 插件 | 后台配置、群与身份过滤、指令解析、异步 HTTP、消息输出。 | 不直连 MySQL，不计算或发放签到奖励，不保存网站密码。 |
| WordPress 桥接插件 | 最小 API、绑定确认页面、专用凭证管理、本人资料、签到编排、公开文章查询。 | 不修改父主题，不复制完整用户中心，不实现支付、会员或通用远程管理。 |
| 原有 Zibll | 用户头像与展示规则、等级、积分、签到状态、奖励和相关 Hook。 | 不要求主题新增机器人专用功能。 |

需要伴随插件的原因：原生 WP REST 无法一次满足 Zibll 积分/等级/签到、本人绑定和评论计数；现有主题 REST 扩展也不是完整的第三方业务接口。[W1][W3][Z6] 新增范围仅限完成这些需求所需的桥接，不新增独立 Web 服务、Redis、青龙面板或消息队列。

### 3.2 本期采用的明确口径

- 一个 AstrBot 插件配置连接一个网站；不做多站切换。
- 所有业务指令在允许的群中使用，不以“必须支持私聊”作为前提。
- 绑定按具体群中的真实平台身份隔离；不默认跨群共享同一个平台用户标识。
- 文章指 WordPress 普通文章 `post`；最新和搜索不混入论坛帖子、商城商品或页面。
- 搜索默认按文章标题关键词匹配。这样不从隐藏、付费正文的关键词命中间接暴露内容；不默认承诺与站内全文搜索完全一致。
- 个人文章数使用网站既有“已发布普通文章”统计口径；评论数使用网站既有已审核评论口径，详见第 5 节。
- 默认以“头像图片 + 文字”回复，不新增生成式图片、HTML 截图卡片或外部图片渲染服务。
- 不做自动签到、定时推文、主动广播、发文、评论写入、积分转账或榜单。

## 4. 群成员身份、账号绑定与指令

### 4.1 身份键

身份取自 AstrBot 真实事件的 `platform_id`、`self_id`、`group_id`、`sender_id`，再加入稳定的站点集成 `client_id`。平台账号值按字符串处理，不转换为整数；不能信任指令中自填的 QQ 号、昵称、UID 或转发消息中的作者信息。[A7]

本期身份范围：

```text
scope = client_id + platform_id + bot_self_id + group_id
actor = scope + sender_id
```

实际存储使用无歧义编码后计算的摘要作为索引，原始字段用于必要的归属核验。`client_id` 不随密钥轮换改变。每个 actor 只能绑定一个 WP UID；同一 scope 内一个 WP UID 只能绑定一个 actor。跨群可以分别绑定同一网站账号，但签到的锁和每日去重必须按网站 UID 统一，不能按群分别发奖。

网站只能确认请求来自受信任机器人及已授权绑定，不能独立证明上游消息平台身份真实性；适配器正确提供身份是必须验证的信任前提。

### 4.2 绑定流程

1. 群成员发送绑定指令，机器人先检查群白名单及真实身份，向网站申请一次性挑战。
2. 网站生成至少 128 位随机挑战，保存摘要、actor、来源群、创建时间、10 分钟有效期和状态；新申请使该 actor 旧的未完成挑战失效。
3. 机器人返回网站绑定链接。链接不含网站 UID、密码、Cookie 或集成密钥；它本身不能建立绑定。
4. 用户在网站正常登录。网站页面显示待绑定的平台/群身份以及将向群展示的八项资料、签到授权范围，明确告知积分会随本人查询展示到群。
5. 用户以当前登录网站账号提交授权，服务端验证登录态和 CSRF nonce，锁定候选 UID。未登录、过期、已消费、已撤销或存在绑定冲突时拒绝。
6. 用户在原群发送“绑定确认”指令，机器人只对同一 actor 返回候选网站昵称和 UID 的核对提示；然后用户发送“绑定确认 UID”完成确认。
7. 服务端比对真实 actor、挑战状态、候选 UID 及唯一约束，原子建立绑定并消费挑战。确认指令中的 UID 只是核对值，不能覆盖网站授权产生的 UID。

链接可能在群内被别人点击，因此不能“打开链接即绑定”，也不能“网站登录一次就自动绑定”。他人抢先授权只会形成错误候选；发起人可以拒绝确认并重新申请。候选一旦锁定不能被后续点击静默替换，避免确认过程被调包。

不使用后台轮询任务。用户主动执行确认指令读取挑战状态；密钥不进入浏览器。绑定页面禁用共享缓存，设置合适的 Referrer-Policy，日志不记录完整挑战令牌。

### 4.3 解绑与失效

- 群内“解绑”先显示当前绑定 UID，再由同一 actor 在短时限内发送“解绑 确认”；不能删除他人的绑定。
- 网站绑定页面允许当前登录用户撤销自己的授权，需再次检查 CSRF 和归属。网站撤销后，下一次资料查询或签到立即失效。
- 网站用户被删除时清理或失效相应绑定；禁止登录状态不因机器人通道被绕过。封禁处理遵循主题规则。
- 不自动覆盖已有绑定。更换网站账号先解绑，再重新授权。

以下为拟定默认值，全部可在 AstrBot 插件后台修改；斜杠表示指令内容的一部分，最终与目标核心的唤醒前缀/@策略联调，不能通过绕过核心群策略实现触发。

| 功能 | 默认示例 | 是否要求绑定 | 返回 |
| --- | --- | --- | --- |
| 发起绑定 | `/网站绑定` | 否 | 网站登录授权链接及有效期。 |
| 查看/完成绑定确认 | `/网站绑定确认`、`/网站绑定确认 123` | 否 | 候选账号核对提示，或绑定完成。 |
| 解绑 | `/网站解绑`、`/网站解绑 确认` | 是 | 二次确认提示，或解绑完成。 |
| 本人资料 | `/网站资料` | 是 | 八项本人资料。 |
| 网站签到 | `/网站签到` | 是 | 签到结果、当前积分、连续/累计签到天数；不臆测实际奖励。 |
| 最新文章 | `/网站最新` | 否 | 最新公开文章列表。 |
| 文章搜索 | `/网站搜索 子比` | 否 | 标题关键词匹配列表。 |

最新/搜索不要求账号绑定，因为只返回公开文章；但仍要求机器人允许的群、调用限流及网站接口认证。

### 4.5 自定义指令实现要求

- 在 `_conf_schema.json` 定义七个命令字段，内部业务动作 ID 不随显示文字变化。[A3]
- 初始化/重载时生成精确匹配表；拒绝空值、重复值、控制字符及无法确定命令边界的配置，不支持用户自填正则表达式。
- 无参数指令必须完整匹配；搜索、确认、解绑只在“完整命令 + 明确空白边界”后解析参数，不能用子串包含判断。
- 过滤阶段只接受预期的文本指令和可选的对机器人 @；不从图片、转发消息、引用正文中提取可执行指令。
- 不注册“所有群消息都通过、handler 内再判断”的粗过滤器。精确匹配必须发生在 AstrBot 的唤醒判断之前，否则可能意外唤醒普通聊天。[A4][A5][A6]
- 配置保存后的最低承诺是按目标版本标准流程重载后生效；不在未验证前宣称无感实时热更新。
- 命中自身指令后阻止继续进入其他业务/LLM；未命中时不拦截、不改变其他插件行为。对同名第三方命令至少提示冲突，不宣称能自动发现所有第三方自定义过滤器。

## 5. 本人资料的数据定义

### 5.1 八项字段

| 字段 | 取值与口径 | 处理边界 |
| --- | --- | --- |
| 头像 | `zib_get_user_avatar_url(uid, size)`，走 Zibll 自定义头像、外部头像及默认头像选择。[L2] | 当前实现可能返回 `//host/path`，按网站协议规范化；不直接假定 WP `get_avatar_url()` 与主题显示一致。 |
| 昵称 | `get_userdata(uid)->display_name`，与主题用户名链接正文一致。[L7] | 不是登录名、群昵称或 `user_nicename`；不把含徽章/链接的整段 HTML 当昵称输出。 |
| 加入网站天数 | `user_registered` 按 UTC 解释后转站点时区，与网站当天日期做自然日差，再加 1。[L8] | 注册当天为第 1 天，显示“加入网站第 N 天”；日期无效或在未来时返回不可用，不编造天数。 |
| 等级 | 用户成长等级，不是 VIP 等级。读取 `level`，缺值按主题初始 1 处理，再按 `user_level_max` 截断。[L3] | 目标主题 `zib_get_user_level()` 缺值时会写入 1；只读资料接口采用经源码核对的纯读分支，不因查询创建 meta。 |
| UID | 绑定对应的 WordPress 用户 `ID`。 | 每次由服务端绑定解析，客户端不能传任意 UID 替代。 |
| 积分 | `zibpay_get_user_points(uid)` 的整数值。[L5] | 与 `level_integral` 经验值区分；只读，不直接写 `points`。 |
| 已发布文章数 | `zib_get_user_post_count(uid, 'publish', 'post')`，完整整数。[L4] | 不计草稿、待审、私密、回收站、论坛帖或商品；这是主题已发布数量口径，不额外排除已发布的付费/密码文章，也不公开这些文章的详情。 |
| 评论数 | `get_user_comment_count(uid, 'approve', false)`。[L2] | 已审核评论；普通文章评论，加上论坛开启时的 `forum_post` 评论；`false` 禁止返回 `1k` 等缩写，不以邮箱猜测游客评论归属。 |

积分、等级功能关闭时，该字段显示“网站未启用”，不能伪造为 0 或 Lv.1。网站用户不存在、绑定已撤销或接口无法确认身份时，不能返回任何旧缓存的个人资料。

评论数选择跟随网站用户中心现有口径，而非另建“只统计普通文章”的新规则。该函数没有额外限定父文章状态，因此不把这一数字表述为“公开文章评论数”；这里只展示本人聚合计数，不返回评论正文或目标文章。文章计数和群内可见文章列表因此可能不同，属于明确口径，不是查询失败。

### 5.2 返回形态

正常情况使用一条图片消息加文字字段，示意数据不来自现有真实用户：

```text
[网站头像]
昵称：示例成员
UID：123
加入网站：第 365 天
等级：Lv.5
积分：1200
已发布文章：18 篇
评论：36 条
```

头像下载必须限制超时、大小、实际图片格式和目标域名；默认只允许站点域名，站点使用头像 CDN 时由管理员明确加入允许列表。每次重定向重新校验地址，禁止访问任意内网、云元数据地址或用户提供的 URL。本机开发地址只作为显式测试例外。

平台不能直接访问头像 URL 时，可由机器人安全下载后发送图片字节或位于本项目运行数据目录的临时文件，使用后删除。网络故障可降级为文字并提示头像暂不可用，但“文字降级可用”不计为头像功能通过验收。

响应只包含上述资料及必要的开关/状态，不返回邮箱、手机号、真实姓名、IP、登录名、用户角色、订单、积分流水或 WordPress 原始用户对象。

## 6. 网站签到设计

### 6.1 必须复用的主题链路

```text
核验集成签名和群成员绑定
  -> 网站用户及签到/禁封状态检查
  -> 获取该网站 UID 的签到互斥锁
  -> 重新读取今日签到状态
  -> zib_user_checkin(uid)
  -> 主题写签到记录并触发 user_checkined
  -> 主题积分/经验监听器按原有规则处理
  -> 校验签到结果并读取当前积分、连续/累计天数
```

已核实的关键事实：

- `zib_user_checkin()` 检查开关、今日是否已签、禁封；保存明细、累计/连续天数和奖励周期，再触发 `user_checkined`。[L1][Z2]
- 积分与经验分别由该 Hook 的既有监听器处理，不是桥接层再发一次。[L3][L5]
- 签到按 `current_time('Y-m-d')` 使用网站时区。机器人本地时区、消息发送者时区和 UTC 日期不能代替网站日期。[L1]
- 连续签到展示天数与连续奖励周期不是同一个字段；不能把最大 7 天奖励周期当成累计连续签到天数。[Z2]
- 主题返回的 `points`、`integral` 是当次规则奖励值；免费积分/经验可能因每日上限或开关而未实际增加。[L3][L5]
- 核心签到不是覆盖所有写入及 Hook 的原子事务；签到函数执行成功不自动证明所有奖励持久化成功。[L1][L5]

### 6.2 幂等与跨入口并发

最低目标：同一网站 UID 同一天从多个群、多条消息、多个机器人请求及网页同时签到，不能因本插件引入重复奖励。

1. 互斥键按“当前网站 + WP UID”建立，不能只使用本进程 `asyncio.Lock`、群 ID 或当日日期。
2. 目标 MySQL 可考虑连接级 `GET_LOCK`，超时约 3 秒；实现前验证容器数据库权限、连接释放和异常退出行为，不能把方案当已验证能力。
3. 桥接请求持锁后重新读取当前日期与签到状态，并清理该用户必要的旧 meta 缓存，防止加锁前读取的旧状态继续被使用。
4. 桥接插件在现有 `wp_ajax_user_checkin` 回调之前增加同一把锁的前置守卫，让网页和机器人遵守相同互斥；保留主题原处理函数，使用请求结束释放机制覆盖原回调的退出路径，不改主题文件。
5. 每日操作记录对 `(WP UID, 网站日期)` 建立唯一约束；不能用“先查不存在，再普通插入”代替数据库唯一性。
6. 来自相同平台事件的重投用稳定业务请求 ID 识别，关联 actor、动作和输入摘要；同 ID 不同输入拒绝。已处理事件在短期请求状态表中去重，不能因午夜换日重新执行；网络重试使用新的防重放 nonce，但不能产生新的签到业务。实现时核实适配器消息 ID/时间是否可靠，对过期事件拒绝执行；缺少可靠 ID 时不能宣称具备跨重启的消息级去重，仅每日 UID 约束仍有效。
7. `zib_user_checkin()` 的其他直接调用方不自动受 Ajax 守卫保护。当前定向查阅的主题及相关插件中只定位到主题 Ajax 调用；开发时仍需核对所有实际启用的签到入口。存在无法纳入同一锁的写入方时，不能宣称全站并发保障已通过。

这部分只允许为签到完整性增加最小守卫，不顺带改造网站全部资产函数。并发测试失败或无法证明守卫覆盖时，暂停启用机器人签到，不以“主题有今日判断”替代并发验收。

### 6.3 结果与部分失败

| 状态 | 行为 |
| --- | --- |
| 本次完成 | 确认当日签到明细存在，返回“签到完成”、当前积分、累计及连续天数。 |
| 今日已签 | 返回“今日已签到”，不调用奖励写入；网页先签或其他群先签均相同。 |
| 网站关闭签到 | 返回明确关闭提示，不修改开关。 |
| 禁封/用户失效/未绑定 | 拒绝写入，不自动补绑定或补签。 |
| 并发处理中 | 返回稍后查询提示，不再启动第二次奖励流程。 |
| HTTP 超时 | 先查询同一业务请求/当日签到状态，不盲目重新发起写入。 |
| 状态不明或部分失败 | 标记 `uncertain`，停止自动重放；保留最少诊断信息，不自动补奖、减奖或删除主题签到记录。 |

默认不输出“实际到账 +N”。如展示规则奖励，必须明确标为“网站规则奖励”，同时显示重新读取的当前积分；不能仅用前后余额差认定该差额完全来自签到，因为其他业务可能同时改变积分。

出现“主题已写签到明细，但奖励 Hook 中断”时，重复调用签到不会自然修复奖励。应返回需要核实的状态，不重置今日记录、不再次手动调用 `user_checkined`。受控测试分别核对签到明细、累计/连续天数、积分流水和余额变化。

跨午夜时以网站日期为准。锁不包含日期，防止两个日期的锁并行；执行前后若日期变化、每日记录键与主题落点不一致，进入状态核实而非自动重试。该边界必须作为专门测试，不通过调整共享网站时区来制造测试条件。

## 7. 最新文章与文章搜索

### 7.1 查询规则

| 项目 | 最新文章 | 文章搜索 |
| --- | --- | --- |
| 内容类型 | `post` | `post` |
| 状态 | 仅 `publish` | 仅 `publish` |
| 可见性 | 无密码、允许匿名看到标题和链接；排除站点自定义隐藏内容。 | 相同。 |
| 排序 | 发布时间降序，同时间用 ID 降序稳定排序；忽略置顶置前。 | 标题相关度优先，同相关度按发布时间及 ID 排序。 |
| 参数 | 默认返回 5 条，后台范围 1–10。 | 1–60 个有效字符的关键词，默认最多 5 条，后台范围 1–10。 |
| 输出 | 标题、发布时间、文章链接。 | 同左。 |
| 未返回内容 | 正文、付费资源、下载链接、密码、私密字段。 | 同左；不搜索隐藏正文。 |

最新按发布时间，不按最后修改时间；旧文章编辑后不能变成“最新发布”。付费文章只有在标题和链接本身对游客公开时才可入列，不返回付费正文或自动摘要。

通过网站侧 `WP_Query` 及明确的权限过滤实现；不在机器人端循环翻页下载全部文章。标题搜索可使用目标 WordPress 已存在的 `search_columns=['post_title']` 能力，实现在目标版本核对；不使用默认全正文搜索后仅隐藏响应正文的方式冒充无泄露搜索。[L9][W2]

对于其他插件的可见性限制，需要在服务端查询和输出两个阶段兼容实际规则；仅检查 `post_status=publish` 不足以证明允许公开。过滤后继续有限补取，或返回较少结果并明确，不泄露未授权条目的标题和数量。

### 7.2 输出与错误

```text
最新文章
1. 示例文章标题
   2026-10-21 12:30
   [文章链接]
```

- 用结构化文本组件输出，HTML 实体解码后清除标签和控制字符；按平台规则防止昵称/标题中的 CQ 片段或 `@全体成员` 被当成指令执行。
- 关键词通过请求 JSON 传输，网站侧验证长度和类型，查询采用 WP API；不拼接用户可控 SQL、排序字段或 URL。
- 空关键词提示当前配置的搜索用法；零结果提示未找到；超时/认证失败提示服务异常，不能伪装为“暂无文章”。
- 本期不增加翻页命令、全文阅读、截图摘要、RSS 定时推送或 LLM 总结。
- 初期不新增持久化文章缓存。先测目标副本响应，确需短缓存时只能缓存公开结果且明确有效期；不得为性能忽略下架和权限变更。

### 8.1 AstrBot 插件 WebUI

| 配置组 | 字段 | 默认或约束 |
| --- | --- | --- |
| 网站连接 | API 基址 | 管理员配置；正式环境 HTTPS，禁止 URL 内携带用户名/密码；不接受群消息修改。 |
| 网站连接 | 用户可访问的网站地址 | 与 API 内网地址分开，供绑定和文章链接使用；校验与目标网站一致，不能任意重定向。 |

| 群权限 | 允许的平台实例及群 ID | 默认空即不响应，不能把空名单解释为所有群开放。网站侧同步限制授权范围。 |
| 指令 | 绑定、确认、解绑、资料、签到、最新、搜索 | 使用第 4 节默认值，全部可改；保存重载时校验冲突与边界。 |

| 网络 | 请求超时 | 建议总超时 15 秒、连接超时 3 秒；重试总预算有上限，签到不能套通用写入重试。 |
| 头像 | 允许的图片域名 | 默认网站域名；CDN 由管理员显式填写，不接受通配所有域名。 |

限流、挑战有效期和消息长度先采用固定保守值，避免为一次需求堆叠大量后台参数。默认个人冷却可设 3 秒、群请求上限每分钟 30 次、绑定申请每人每 10 分钟 3 次，具体数值以正常群使用验证调整；网站侧必须有独立限流，不能只信任机器人。

配置缺失或校验失败时禁用本插件业务并明确提示后台，不让空网址、空凭证或冲突命令以不确定状态运行。`secret: true` 只是 UI 遮罩而非加密，配置文件和备份仍需限制访问。[A3]

### 8.2 WordPress 最小后台

独立桥接设置页只面向具备 `manage_options` 的管理员，使用独立 option，不写入 `zibll_options`：

- 集成启用状态、稳定 client 标识、允许的平台/群范围。
- 生成、撤销、轮换本项目专用密钥；不创建管理员应用密码。
- 查看连接必要条件：主题及函数是否存在、签到/积分/等级开关、站点时区。
- 不增加奖励参数、积分管理、群成员全量导出或通用 SQL/代码执行入口。

生成/轮换凭证需要后台 nonce 与能力检查。服务器需要保留 HMAC 密钥以验签，不能声称只存单向摘要就可完成 HMAC；配置存储关闭 autoload、限制访问，密钥仅在生成时供管理员复制。浏览器授权页不读取该密钥。

## 9. 桥接接口契约与安全要求

### 9.1 拟定端点

命名空间拟为 `/wp-json/astrbot-zibll/v1`；其中 `v1` 仅表示接口命名空间，不是本轮给插件新增发布版本。下表是待实现协议，不代表当前网站已经提供这些端点。

| 方法与路径 | 输入重点 | 输出/权限 |
| --- | --- | --- |
| `GET /capabilities` | 集成签名 | 最小能力、站点时区、协议能力标识；不公开用户计数和原始插件列表。 |
| `POST /binding/start` | 真实 actor、请求 ID | 一次性链接和有效期；校验群范围、限流。 |
| `POST /binding/status` | 同一 actor | 待确认状态及候选账号最小信息；不能查询其他 actor。 |
| `POST /binding/confirm` | actor、挑战标识、期望 UID | 仅确认网站已授权的候选 UID。 |
| `POST /binding/revoke` | actor、二次确认状态 | 撤销本人的有效绑定。 |
| `POST /profile` | actor | 服务端解析 UID，返回第 5 节白名单字段。 |
| `POST /checkin` | actor、稳定业务请求 ID | 按第 6 节执行，不能接收奖励数额。 |
| `POST /checkin/status` | actor、业务请求 ID | 用于超时后的状态核实，不发奖励。 |
| `POST /articles/latest` | 限制后的条数、群来源 | 安全公开文章列表。 |
| `POST /articles/search` | 关键词、条数、群来源 | 安全公开文章列表。 |

读取端点采用 POST 的主要原因是把 actor 等参数放入签名覆盖的 JSON 请求体，减少个人标识进入 URL/代理日志；这不允许其修改用户业务数据。网站浏览器授权/撤销处理另走登录 Cookie + nonce，不共用机器人的认证方式。

接口应统一返回 `request_id`、业务状态 `code`、安全 `message` 和白名单 `data`，错误映射至少区分：

| HTTP/业务状态 | 含义 |
| --- | --- |
| 400 | 参数或指令语法不合法。 |
| 401 | 缺少/错误签名、失效密钥或时间校验失败。 |
| 403 | 群不允许、用户被限制或授权不满足。 |
| 404 | 当前 actor 无绑定或目标账号已失效；不提供他人 UID 枚举详情。 |
| 409 | 绑定冲突、重放、并发处理中或需核实的操作状态。 |
| 429 | 限流，返回合理的重试等待信息。 |
| 503 | 主题能力不兼容、依赖不可用或服务暂时不可用。 |
| 200 + `already_checked_in` | 今日已签，是可解释的幂等结果，不再写入。 |

### 9.2 机器认证

采用专用共享密钥的 HMAC-SHA256 请求签名，密钥由安全随机源生成至少 32 字节，使用 PHP/Python 标准密码学函数，不自创加密算法。本机 PHP 已确认具备 `hash_hmac`、`hash_equals`、`random_bytes`，但完整协议尚未实现。

建议签名串按固定顺序包含协议标识、client_id、key_id、HTTP 方法、规范 REST 路由、UTC 时间戳、随机 nonce、原始请求体 SHA-256。跨语言测试必须固定字节编码和换行规则。

- 业务参数只放 JSON；除 WordPress `rest_route` 路由兼容参数外拒绝未签名的查询参数。网站用实际解析的规范路由验签，避免固定链接与查询路由产生歧义。
- 校验时间窗口建议为前后 180 秒；nonce 至少 128 位随机，在网站侧以唯一约束原子登记并保留不少于窗口的有效期。
- 验签、client/群范围和参数校验成功后才进入业务。nonce 去重与业务请求幂等是两个层次，不能混用。
- 使用恒定时间比较；不在 URL、群消息、异常堆栈或日志打印密钥和 Authorization/签名头。
- 正式环境验证 TLS 证书，不使用 `verify=False`；认证请求禁止自动把凭证跨域重定向。
- 仅本机开发允许管理员显式配置 HTTP；不能把本机例外复制到公网。
- WordPress 路由均有明确 `permission_callback`；不是因为使用自定义 HMAC 就把其设为无条件通过。[W5]

### 9.3 权限、隐私与缓存

绑定决定“这个群成员可以以哪个网站用户身份执行哪些操作”，集成密钥只证明“请求来自哪个机器人”。两者必须同时成立，不能把机器人认证等同于有权操作任意 UID。

所有写入使用绑定所得 UID，主题函数尽量显式传 UID；如调用确实依赖当前 WP 用户上下文，仅在已授权请求内临时切换并恢复，不设置登录 Cookie、不获得管理员身份。

本插件只读本人八项资料和公开文章，只允许签到/绑定/解绑三类业务写入。不把接口注册为 LLM 工具，不让自然语言模型自行决定给某用户签到。

个人接口、绑定页与签到响应必须 `no-store/private` 并排除 CDN、Nginx 和 WP-Optimize 共享缓存；仅加 HTTP 头不等于所有缓存层必然遵守，需实测两账号不串号。首次实现不缓存绑定和个人资料，以便撤销立即生效。

| 消息唤醒 | 当前官方源码在 handler 过滤通过后设置 `is_wake=True`；过滤在 handler 执行前发生。[A6] | 禁止仅注册全量群消息监听、进入 handler 后才判断指令。普通聊天必须在过滤阶段返回不匹配，否则可能改变其他插件或 LLM 的唤醒行为。 |
| 平台身份 | 事件提供 `get_platform_id()`、`get_self_id()`、`get_group_id()`、`get_sender_id()`；平台类型不等于平台实例 ID；`unified_msg_origin` 表示会话来源。[A7] | 身份取自真实事件，不接受用户手填平台账号冒充身份；群会话 ID 不能单独作为群成员身份。是否跨群、跨私聊复用身份须按具体适配器验证。 |
| 头像与文本 | 官方支持 `Plain`、`Image.fromURL()` 与消息链，支持 URL 图片回复；不同平台富媒体能力存在差异。[A8] | 默认头像图片加文字字段，不新增图片卡片生成服务。图片失败允许文字降级，但不能把降级验收算成头像发送通过。 |
| 生命周期 | 官方提供 `terminate()`，插件停用或卸载时调用。[A2] | 后续关闭 HTTP 会话、清理本插件临时状态；配置保存后按实际版本重载插件，验证旧指令失效及无重复 handler。 |
| Logo | 官方约定插件根目录 `logo.png`，长宽比 1:1，推荐 256×256。[A1] | 采用用户提供的本地素材，不另行生成 Logo；具体原始文件和规格以资源目录实际检查为准。 |

**自定义指令的拟定验收方式：** 所有对群成员开放的指令名称或别名在插件 WebUI 可配置；保存并按目标版本要求重载后，新名称有效、旧名称不再触发。禁止空指令、重复名称和歧义前缀；关键词参数只按明确命令边界解析。测试普通聊天、不相关前缀、其他插件指令、机器人被 @、唤醒前缀和配置重载的组合，不以“handler 能收到消息”代替正确路由验收。动态路由的具体注册方式在目标 AstrBot 版本锁定后落实。

### WordPress 原生 REST 能力与边界

| 原生能力 | 官方核对结果 | 规划结论 |
| --- | --- | --- |
| 用户字段 | `/wp/v2/users` 包含 `id`、公开显示名 `name`、`avatar_urls`；`nickname` 和 `registered_date` 属于 `edit` 上下文。[W1] | 不能假定匿名 REST 可得到完整个人资料；昵称须按网站实际展示口径读取，而不是群昵称。 |
| 等级、积分、签到 | 用户标准 Schema 没有 Zibll 等级、积分或签到业务字段。[W1] | 需网站侧最小伴随桥接插件调用已核实的主题能力，不能只靠 AstrBot 查询 WP 原生接口完成全部需求。 |
| 最新文章、搜索 | `/wp/v2/posts` 提供 `search`、`author`、`page`、`per_page`、`orderby`、`order`、`status`；默认状态为 `publish`，日期排序和修改时间排序是不同选项。[W2] | 最新文章以首次发布时间排序，而不是修改时间。桥接层只返回公开文章安全字段；不因机器人连接有权限而泄露草稿、私密或受限正文。 |
| 个人评论数 | 评论接口的 `author` 参数需要授权；官方控制器将其列为受保护参数，无相应权限不能按该参数过滤。[W3][W4] | 不采用匿名查询 `/wp/v2/comments?author=UID` 的假设，也不为计数给群成员发文权限。由桥接服务按已绑定 UID 统计所需数量，不返回评论邮箱、IP 等信息。 |
| 自定义端点 | 可在 `rest_api_init` 注册独立命名空间及路由，定义参数验证、清洗、允许方法和 `permission_callback`。[W5] | 桥接端点只开放此次所需操作；服务认证、绑定归属及操作权限分别检查。受保护端点不得以 `__return_true` 代替鉴权。 |
| 网站登录授权 | WP Cookie REST 请求使用 `wp_rest` nonce，可通过 `X-WP-Nonce` 发送；nonce 不替代用户权限检查。[W6] | 网站上的绑定确认用正常登录态和 CSRF 防护；浏览器不接触机器人集成密钥，机器人不索取用户密码或登录 Cookie。 |
| Application Passwords | WP 5.6 起提供应用密码，官方支持通过 HTTPS Basic Auth 调用 REST。[W6] | 仅作方案比较：当前目标副本禁用了该能力，主方案不解禁、不依赖应用密码，采用独立集成密钥的受限桥接认证。 |

由上述接口边界推导，本项目采用“AstrBot 指令插件 + 单站 WordPress 最小伴随桥接插件”而不是直接读取数据库、模拟网页登录或向机器人提交个人 Cookie。桥接插件中的 Zibll 函数、数据字段和签到规则须以本地主题及 MCP 证据为准；WP 文档不能证明 Zibll 的额外行为。

### 实施前需要落地的版本与联调条件

1. 确认目标 AstrBot 安装版本、部署方式、消息适配器和真实群；对该版本复核配置加载、过滤器、重载及图片发送。
2. 验证平台实例、机器人 ID、群 ID、发送者 ID 的真实值和稳定性，不把 QQ 官方群成员标识、OneBot QQ 号或其他平台账号一概视为同一种身份。
3. 账号绑定必须让网站登录用户确认授权，并让发起绑定的同一群成员核对、确认最终网站 UID；绑定链接本身不能直接完成绑定。
4. 主题等级、积分、头像、签到日期边界、签到奖励和评论计数口径以目标站实际实现为准；原生 REST 的存在不能替代业务校验。
5. 在允许测试部署桥接插件前，需确认副本插件启用限制及需要的最小放行；本规划阶段不修改隔离策略。
